# 0013: Imported/uploaded unmanaged certificates

Status: accepted (Phase 4A)

## Context
Not every certificate an operator wants CertForge to store, deploy and let agents pull was issued by CertForge itself: an existing PEM/PKCS#12 bundle someone already has (Task 13, this ADR), or a whole acme.sh/certbot state directory (Task 14), needs a home in the same `certificates`/`certificate_versions` tables the ACME issuance flow already uses — the deployment, grant, layout and export machinery built for a managed certificate should work identically for one CertForge did not issue. Two questions follow: how to mark a certificate CertForge must never renew, and how to store a version whose private key CertForge was never handed.

## Decision
- **A boolean, not a new status.** `certificates.managed boolean NOT NULL DEFAULT true` (migration 00011) sits beside the existing `status` column rather than folding "unmanaged" into it. `status` already means "where is this certificate's own lifecycle" (`pending`/`active`/`failed`/`expired`/`revoked`) — a lifecycle an unmanaged certificate still has (it becomes `expired` exactly like a managed one, once its current version's `not_after` passes; `MarkExpiredCertificates` does not filter on `managed`). `managed` is an orthogonal fact: whether the *issuance worker* is allowed to touch this row at all. Collapsing the two would mean either inventing `unmanaged-active`/`unmanaged-expired`/… duplicating every status, or losing the distinction. `CHECK (managed OR next_renew_at IS NULL)` makes the pairing a database invariant, not just a convention the Go code has to remember: an unmanaged certificate structurally cannot be due, so `ListDueCertificateIDs`' `AND managed` is defense in depth, not the only thing stopping the scheduler.
- **Keyless versions are real rows, not a special case.** `certificate_versions.private_key` (a `crypto.EnvelopeBox`-sealed PKCS#8 blob, same as an issued version's) becomes nullable rather than adding a parallel "keyless_versions" shape. `certstore.Material(..., withKey=true)` on a NULL key returns a nil `PrivateKeyPKCS8` with no error (pre-flight ruling C1); only a renderer that actually needs the key (`der`/`key`, `p12`, `jks`, or the PEM `key`/`combined` parts) raises `render.ErrNoKey`, at the point that render is attempted, not at storage time. This lets a cert-only PEM layout (`fullchain`, say) render and deploy against a keyless upload exactly as it would against a keyed one — no separate code path, because there is no separate shape to special-case.
- **Renewal is refused, not silently skipped.** `renewCertificate` and `updateCertificate` 409 "managed externally" for `managed=false` rather than treating the request as a no-op or auto-converting the certificate to managed. Both would surprise an operator: a no-op renew looks like it worked from the response but never touches anything, and an implicit conversion means CertForge starts trying to issue against names it may have no CA, account or verification rule configured for. Refusing is explicit; `uploadCertificateVersion` is the one write path onto an unmanaged certificate's material, and it is refused (409, the opposite direction) once the certificate becomes managed.
- **The keyless-grant rule runs at grant time, not render time.** `createGrant`/`updateGrant` check `delivery.NeedsKey(layout) || target != nil` against the certificate's current version up front (422 on `certificateId`) rather than letting the grant succeed and then failing to deploy with `ErrNoKey` down in `agents.render`. A grant is a standing declaration ("this client should have this certificate, this way"); failing it immediately at the point the operator chose an incompatible layout/target is a clearer signal than a grant that is accepted and then perpetually stuck in a failed deployment state. The reverse direction — uploading a keyless version onto a certificate that already has a live grant needing a key — is caught symmetrically by `uploadCertificateVersion` (409), checked inside `internal/issuance.Service.UploadVersion`'s own transaction via the `KeylessGrantHook` func field (wired in `cmd/certforge/serve.go` to `agents.LiveGrantsNeedKeyTx`, a plain function rather than an `agents.Service` method) rather than `internal/issuance` importing `internal/agents` directly, since issuance must not import agents (R7): the two packages stay acyclic, wired together by main's own composition root instead of one importing the other.

## Consequences
- A certificate's full state is `(status, managed)`, not `status` alone; every place that reads `status` to decide what a certificate is doing (the scheduler, the list/detail API, the web UI) must also consider `managed` where renewal or editability is the question. `Certificate.managed` is a required field on the API schema specifically so no client can read `status` and assume renewal applies.
- A keyless version is genuinely useless for some deployments (a p12/jks export, a DER key part, a Traefik target) and only discovered to be so at render time for any renderer besides the grant-time `NeedsKey` check (for example a plain `downloadCertificateVersion?parts=key` on a keyless version, which 404s the same way a missing part always would, not 422). This is accepted: teaching every render path to pre-validate against "does this version have a key" the same way grants do would duplicate the grant-time check for comparatively little benefit, since a download is a one-off request an operator can simply retry with different parts.
- `internal/issuance` and `internal/agents` remain acyclic (neither imports the other), which is why the upload endpoints' keyless-grant checks are split: `internal/issuance.Service.KeylessGrantHook` (a func field the composition root sets to the plain function `agents.LiveGrantsNeedKeyTx`, called from inside `UploadVersion`'s own transaction) and `internal/agents`' `checkRefs` (called from `CreateGrant`/`UpdateGrant`) are two separate entry points into the same underlying fact (does a grant's layout/target need a key), rather than one shared function either package could call directly.
